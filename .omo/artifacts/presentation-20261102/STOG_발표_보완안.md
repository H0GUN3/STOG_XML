## 2쪽. [초안] 여행 준비는 왜 번거로운가

(찾을 때)
- 맛집은 인스타, 숙소는 예약 앱, 후기는 블로그에서 따로 찾는다

(모을 때)
- 친구와 카톡으로 링크를 주고받는다
- 며칠 뒤에는 그 링크가 어디 있는지 찾기 어렵다

(다녀온 뒤)
- 여행 사진이 일상 사진 사이에 섞인다
- 내가 어디를 다녀왔는지 한눈에 볼 방법이 없다

**배치:** 기존 4·5·6쪽 이미지를 세 칸으로 나란히.

**말할 내용:** 여행 한 번에 앱을 여러 개 오가고, 모은 정보는 채팅방에 묻히고, 다녀온 기록은 갤러리에 묻힙니다. 이 세 장면을 하나로 잇는 것이 STOG의 출발점입니다.

## 3쪽. [초안] STOG는 이렇게 해결한다

(여행 바구니)
- 인스타 링크를 공유하면 장소를 찾아 여행 바구니에 담는다
- 바구니에서 골라 일정에 넣는다

(함께 짜는 일정)
- 친구와 같은 일정표를 함께 고친다
- AI가 동선과 일정 초안을 제안한다

(방문 지도)
- 여행지에서 앱으로 사진을 찍으면 지도의 육각형 칸(CELL)이 채워진다
- 칸을 누르면 그곳에서 찍은 사진과 기록을 다시 본다

**다른 여행 앱과의 차이: 계획으로 끝나지 않고, 실제로 다녀온 곳이 사진 지도로 남는다**

**배치:** 기존 8·9·10쪽 아이콘 흐름을 한 줄씩. 기존 7쪽 비교표를 쓰려면 이 쪽 아래에 작게 넣는다.

## 4쪽. [구체화] 초안을 실제 기능으로 바꾸기

| 초안의 말 | 개발하며 정한 내용 |
| --- | --- |
| 함께 여행을 준비한다 | 여행을 하나 만들고 초대 링크로 친구를 부른다. 모든 기능은 "어느 여행의 일인가"를 기준으로 동작한다 |
| 함께 일정을 고친다 | 제목·지역·날짜는 구성원 누구나 고친다. 멤버 내보내기와 역할 변경은 관리자만 한다 |
| 링크를 바구니에 담는다 | 바구니에는 링크가 아니라 "장소"를 담는다. 검색으로 찾든 링크에서 찾든 같은 장소 정보로 저장된다 |
| 바구니에서 일정으로 옮긴다 | 복사하지 않고 같은 항목의 상태만 "바구니"에서 "일정"으로 바꾼다 |
| 방문을 지도에 남긴다 | 방문 인정 조건을 먼저 정했다 (다음 쪽) |

**말할 내용:** 초안의 문장은 그대로 만들 수 없어서, 사용자가 실제로 누르는 동작으로 하나씩 풀었습니다. 이 과정에서 "여행"이 모든 기능의 기준이 됐습니다.

## 5쪽. [구체화] 실제 상황으로 정한 규칙

(두 사람이 동시에 고치면?)
- 먼저 저장한 내용을 덮어쓰지 않는다
- 나중에 저장한 사람에게 "다른 사람이 먼저 수정했다"고 알린다

(인터넷이 끊겨 저장을 두 번 누르면?)
- 여행이나 바구니 항목이 두 개 생기지 않는다
- 서버가 이미 처리한 요청인지 확인한다

(저장하다가 오류가 나면?)
- 저장은 전부 성공하거나 전부 취소된다. 반쯤 저장된 상태가 남지 않는다
- 일정 기능을 만들어도 옮기다 실패한 장소가 바구니에서 사라지지 않게 한다

(사진을 보기만 해도 칸이 채워지면?)
- 검색, 링크 저장, 갤러리 사진, 친구 사진 보기로는 CELL이 채워지지 않는다
- 앱으로 직접 찍었거나, 직접 시작한 기록 중에 확인된 방문만 인정한다

(여행 사진은 누가 볼 수 있나?)
- 그 여행의 구성원만 볼 수 있다
- 주소를 알아내도 구성원이 아니면 열리지 않는다

**말할 내용:** 기능 목록보다 이런 상황을 먼저 정했습니다. 동시 수정, 중복 저장, 사진 권한 규칙은 지금 코드에 적용했고, 일정 이동과 방문 인정 규칙은 해당 기능을 구현할 때 적용합니다.

## 6쪽. [구조] 화면 흐름도

```text
로그인 ─ 회원가입
   │
   ▼
 하단 탭 4개
   ├ 홈 ─ 여행 카드, 새 여행 만들기
   ├ 내 여행 ─ 새 여행 만들기, 초대 링크로 참여
   │    └ 여행 상세
   │         ├ 여행 정보 수정
   │         ├ 여행 멤버, 초대 링크
   │         └ 장소 찾기 → 장소 상세 → 바구니에 저장
   ├ 발견 ─ 피드
   └ 사용자 ─ 프로필
```

**배치:** 박스와 화살표로 슬라이드 전체에 그리고, 박스마다 실제 화면을 작게 넣는다.

## 8쪽. [구조] 기술 스택

(앱)

- Fragment, View Binding, RecyclerView, Material: 화면 전환, 목록, 디자인

- Spring Security: 로그인 확인

- Flyway: 테이블 변경 이력을 파일로 관리
- 서버 비공개 폴더: 여행 사진 저장

(11월 추가 예정)
- 지도, 위치를 육각형 칸으로 바꾸는 H3(서버), AI 일정 조정, 실시간 동기화

## 9쪽. [구현] 회원가입 · 로그인 · 홈 (기존 11쪽 화면)

(회원가입 · 로그인)
- 아이디와 8자 이상 비밀번호로 가입한다. 너무 흔한 비밀번호는 거절한다
- 비밀번호는 PBKDF2로 60만 번 변환해 저장한다. 서버 데이터가 유출돼도 원래 비밀번호를 알아내기 어렵다

(다시 켜도 로그인 유지)
- 15분짜리 출입증과 30일짜리 재발급 토큰을 나눠서 쓴다
- 재발급할 때마다 토큰을 새로 바꾸고, 앱에는 암호화해 보관한다

(홈)
- 내 이름으로 인사하고, 내 여행 수를 서버에서 받아 보여 준다
- 진행 중·예정 여행을 최대 3개 카드로 보여 준다
- 카드에 "진행 중 · 1일째", "예정 · D-8", "11.2 ~ 11.5 · 3박 4일"처럼 표시한다
- 대표 사진이 없으면 기본 이미지를 보여 준다

(아직 안 된 부분)
- CELL과 방문 지역 수는 방문 기록을 만든 뒤 계산한다. 지금은 0으로 표시된다

## 10쪽. [구현] 여행 만들기 (기존 12쪽 화면)

(내 여행)
- 내가 속한 여행을 진행 중 → 예정 → 지난 여행 순서로 보여 준다
- 상태는 오늘 날짜와 여행 기간을 비교해 서버가 자동으로 정한다

(달력으로 기간 선택)
- 시작일과 종료일을 차례로 누르면 사이 기간이 칠해지고 "3박 4일"이 표시된다
- 날짜를 직접 입력할 때 생기는 형식 오류를 없앴다
- 새 여행과 여행 수정이 같은 달력을 쓴다

(여행 생성)
- 기간, 지역, 제목을 넣고 만들면 서버에 저장되고, 만든 사람이 관리자가 된다
- 버튼을 두 번 눌러도 여행은 하나만 생긴다

## 11쪽. [구현] 친구와 함께 준비하기 (새 캡처 필요)

(여행 수정)
- 구성원 누구나 제목, 지역, 기간을 고칠 수 있다
- 다른 사람이 먼저 고쳤으면 덮어쓰지 않고 알려 준다
- 기간을 줄였을 때 벗어나는 일정이 있으면 저장을 막는다

(초대 링크)
- 관리자가 기간 제한이 있는 초대 링크를 만들어 친구에게 보낸다
- 친구는 링크와 표시할 이름을 입력해 참여한다
- 필요 없어진 링크는 관리자가 취소할 수 있다

(멤버와 역할)
- 멤버 목록과 역할을 보여 주고, 관리자만 역할 변경과 내보내기를 할 수 있다
- 마지막 관리자는 역할을 내려놓을 수 없어 관리자 없는 여행이 생기지 않는다

(대표 사진)
- 올린 사진은 서버 비공개 폴더에 저장하고, 작은 미리보기도 함께 만든다
- 서버가 구성원인지 확인한 뒤에만 사진을 보내 준다

**말할 내용:** 버튼을 숨기는 것만으로는 권한을 지킬 수 없어서 서버에서도 다시 확인합니다. 지금은 다른 사람의 변경이 화면을 다시 불러와야 보입니다. 바로 반영되는 실시간 동기화는 11월에 구현합니다.

## 12쪽. [구현] 장소 찾기와 바구니 (새 캡처 필요)

(장소 데이터)
- 소상공인 공공 데이터를 가져와 앱 공통 장소 목록을 만들었다
- 대소문자가 달라도 찾을 수 있도록 검색용 이름을 함께 저장한다 (예: STOG와 stog)

(장소 찾기)
- 두 글자 이상 입력해 검색하고, 지역과 카테고리로 좁힐 수 있다
- 결과가 많으면 나눠서 불러온다

(바구니에 저장)
- 장소 상세에서 저장을 누르면 지금 여행의 바구니에 담긴다
- 같은 장소를 다시 담아도 중복으로 쌓이지 않는다

**말할 내용:** 11월에 만들 링크 추출도 결국 이 장소 목록과 바구니로 연결됩니다. 입구만 하나 늘어나는 구조입니다.

## 13쪽. [구현 현황] 화면이 먼저 나온 기능과 완성 예상안 (기존 13·14쪽 화면)

(피드 · 프로필: 화면만 구현)
- 피드 게시물과 프로필의 게시물, 소개, 팔로워 수는 샘플이다
- 프로필의 이름과 여행 수만 실제 데이터다
- 글쓰기, 좋아요, 댓글, 프로필 수정은 아직 동작하지 않는다

(방문 지도: 완성 예상 화면)
- 앱으로 사진을 찍으면 서버가 위치를 육각형 칸으로 바꿔 채운다
- 칸에 그곳 사진이 표시되고, 누르면 위치와 기록을 볼 수 있다
- 채운 칸 수가 홈의 CELL·방문 지역 수에 반영된다

**배치:** 왼쪽에 피드·프로필 캡처, 오른쪽에 CELL 예상 화면. 오른쪽에 "완성 예상 화면"이라고 표시한다.
