# STOG 제품 MVP 범위와 우선순위

작성일: 2026-10-01

## 1. 읽는 법과 결론

제품 기준은 `STOG_Android_App_Project_Specification_v1.4.docx`다. 이 문서의 “확정”은 v1.4가 요구하거나 채택한 제품 계약을 뜻하고, 현재 저장소에 구현됐다는 뜻은 아니다. 현재 구현 상태는 `docs/PLAN.md`를 따로 따른다.

v1.4가 말하는 제품은 여행을 함께 계획하고, 실제 방문 기록을 CELL 지도에 남기며, 장소 발견과 외부 링크를 다시 여행 계획에 연결하는 Android 서비스다. 따라서 첫 MVP는 로그인 화면이나 TripItem 조회만으로 끝내지 않는다. 다음 한 줄을 끊김 없이 증명하는 범위가 가장 작고 coherent하다.

> 사용자가 로그인하고, 여행을 만들고 구성원을 초대하고, 공통 Place를 검색하거나 Instagram에서 가져와 바구니에 넣고, 날짜별 일정으로 옮겨 협업하며, 지도에서 실행하고, 직접 촬영하거나 시작한 기록 세션으로 CELL을 남긴다.

이 문장은 v1.4의 제품 정의와 핵심 완료 조건에 근거한다. [v1.4 §1.1, §4.5, §10, §11, §13]

| 외부 설정 | 외부 provider, 지도, AI, 저장소, 공개 접속은 계정, 무료 한도, 약관, callback, TLS와 비용 차단을 먼저 확인하고 연결한다. 값과 secret은 보고서와 저장소에 기록하지 않는다. | [v1.4 §1.4, §9.2, §12] |

## 3. MVP에 포함할 범위와 단계

아래 순서는 v1.4 §11의 의존 순서를 제품 사용자 여정으로 다시 정리한 **제안 순서**다. 각 기능의 요구는 CONFIRMED지만, 어느 단계까지를 첫 출시로 묶을지는 이 보고서의 MVP 제안이다.

### MVP 0, 공통 기반과 인증

**포함 제안:** 계정 로그인과 로그아웃, 인증된 사용자, 공통 API 오류와 재시도, Java/XML 다섯 탭 골격, 서버 원본 연결.

**확정 요구:** 인증 요청은 서버가 사용자를 식별하고 리소스 권한을 다시 검사해야 한다. 구체 provider 목록은 구현 단계 확정 항목이다. [v1.4 §5.1]

**현재 상태:** Kakao 인증과 local backend는 구현 및 제한된 local 검증이 있으나, production/public E2E는 미실행이다. `docs/PLAN.md`의 상태를 구현 완료로 확대하지 않는다.

**수용 기준:** 정상 로그인 후 보호된 화면에 진입하고 로그아웃하면 보호 요청이 거부된다. 만료, 네트워크 실패, 잘못된 인증은 비밀값을 노출하지 않는 복구 가능한 오류로 표시한다. provider 설정이나 무료 조건이 없으면 연결하지 않고 명시적 설정 오류를 표시한다.

### MVP 1, 여행 생성과 협업 계획

**포함 제안:** 여행 생성과 수정, 진행중·예정·지난 상태 분류, 여행 상세, 구성원 초대 링크, 관리자와 일반 구성원 권한, 여행 삭제와 나가기, 서버 동기화.

**확정 요구:** 여행에는 이름, 대표 이미지, 기간, 지역이 있고, 초대 링크는 발급 후 10분 동안만 신규 참여를 허용한다. 관리자는 삭제할 수 있지만 나갈 수 없고, 일반 구성원은 나갈 수 있지만 삭제할 수 없다. 두 역할 모두 여행 정보, 바구니, 일정은 편집할 수 있다. [v1.4 §4.3, §5.2, §5.6]

**수용 기준:** 여행 생성 뒤 날짜 기준으로 상태가 정확히 분류된다. 유효한 링크로 참여한 두 사용자가 같은 여행을 읽고 수정한다. 만료 링크의 신규 참여는 거부되고 기존 구성원은 유지된다. 관리자에게 나가기와 일반 구성원에게 삭제가 노출되지 않으며, 서버에서도 같은 권한을 강제한다.

**오류 기준:** 없는 여행 또는 비구성원은 다른 여행의 존재를 추론할 수 없는 오류를 받는다. 동시에 같은 버전으로 저장하면 조용히 덮어쓰지 않고 충돌과 최신 조회를 안내한다. [v1.4 §5.7.1, §13]

### MVP 2, 자체 장소 검색과 공통 Place 상세

**포함 제안:** 장소명, 지역, 카테고리 검색, 결과 없음과 네트워크 오류 상태, 공통 지도와 장소 상세, 바구니 저장.

**확정 요구:** 자체 검색은 STOG 서버의 통합 Place를 조회하고, 지도 선택과 상세는 STOBEE의 공통 지도 화면을 재사용한다. 검색 선택만으로 AI를 자동 호출하거나 CELL을 만들지 않는다. 검색 결과와 지도 마커, 상세, 바구니는 동일 Place를 가리킨다. [v1.4 §4.7, §5.4, §5.8]

**수용 기준:** 홈 검색에서 검색어와 결과를 유지한 채 장소 상세로 이동하고 뒤로 오면 목록과 스크롤이 복원된다. 진행중 또는 예정 여행을 선택해 같은 Place를 바구니에 저장한다. 좌표나 이미지가 없으면 대체 상태를 표시하고 임의 좌표를 만들지 않는다.

**외부 전제:** 자체 장소 DB는 공공 관광 및 상권 데이터 수집과 정규화가 필요하다. PostGIS는 거리와 범위, `pg_trgm`은 문자열 검색에 사용하지만 실제 데이터 수집, 중복 매칭, 결과 상한은 별도 검증한다. [v1.4 §7, §7.2, §7.3]

### MVP 3, 바구니와 날짜별 일정

**포함 제안:** 바구니 목록, 삭제 확인, 바구니에서 선택 날짜 일정으로 이동, 일정에서 바구니로 이동 또는 삭제, 날짜별 정렬과 순서 변경, 같은 번호의 지도 마커, 계획 버전 충돌 처리.

**확정 요구:** 바구니와 일정은 같은 TripItem의 날짜와 순서 상태다. 이동 성공 뒤에만 바구니에서 사라지며 실패하면 기존 상태를 보존한다. 재정렬은 조작 종료 시 한 번 저장하고 서버가 여행 소속, 중복, 누락과 순서를 검사한다. [v1.4 §4.3, §4.3.1, §4.3.2, §8.1]

**수용 기준:** 장소를 날짜에 넣으면 일정에 한 번만 나타나고 바구니에는 남지 않는다. X를 누르면 바구니 이동과 완전 삭제를 확인받는다. 순서를 바꾸면 카드 번호, 지도 번호, 동선 순서가 일치한다. 응답이 유실되어 같은 `request_id`를 재전송해도 중복 이동이나 중복 생성이 없다. [v1.4 §5.7.2, §13]

### MVP 4, Instagram 우선 장소 가져오기

**포함 제안:** 공유 수신과 붙여넣기, URL 검증, 비동기 작업 상태, 캡션과 후보 근거, 기존 Place 대조, 사용자 선택, 선택 후보의 바구니 저장, 수동 본문 보조.

**확정 요구:** 외부 링크 유입은 Instagram이 1순위이며 카카오와 네이버 지도 링크는 후속이다. 앱은 입력, 진행, 후보 확인과 저장을 담당하고, 서버가 수집, 파싱, Place 대조를 담당한다. 추출 완료와 저장 완료는 다르며, 사용자 확인 전에는 바구니, 일정, CELL, 발견 게시물을 바꾸지 않는다. [v1.4 §1.3, §4.3.3, §4.3.5, §14.1, §14.4]

**수용 기준:** 정상 URL은 작업 ID를 받고 캡션 확보, 후보 분리, Place 대조, 사용자 확인 단계를 구분해 표시한다. 여러 후보 중 사용자가 고른 장소만 선택 여행에 저장한다. 주소 없음, 후보 없음, 접근 제한, 캡션 불일치, 미해결 Place는 각각 구분한다. 자동 수집 실패 때 붙여넣은 본문은 `user_input` 출처로 표시한다. 같은 확인 요청 재시도는 중복 저장하지 않는다. [v1.4 §13.1, §14.2, §14.8]

**명시적 제외:** 댓글 수집, OCR, 영상 음성, 원본 사진 재게시, 로그인이나 CAPTCHA 우회, 개인 쿠키 재사용, 자동 일정과 CELL 생성, Instagram 전용 Place DB와 개인 보관함은 MVP에서 제외한다. [v1.4 §14.1]

**외부 전제:** 실제 Instagram 대상 형식, 자동 수집 허용, Playwright와 Chrome 환경, 서버 재검증, URL와 SSRF 방어, 작업 만료와 자원 회수를 확인해야 한다. v1.4의 두 URL 결과는 구현과 운영 성공률의 증거가 아니다. [v1.4 §14.11, §14.12, §14.13]

### MVP 5, 지도 중심 여행 실행

**포함 제안:** 홈의 여행 카드에서 지도 중심 실행 화면 진입, 날짜 선택, 일정 인덱스 마커와 연결 동선, 공통 장소 상세 시트, 범위와 줌에 따른 필요한 데이터만 조회.

**확정 요구:** 홈 여행 카드 선택은 일반 편집 화면이 아니라 지도와 바텀시트가 결합된 실행 화면으로 간다. 일정 마커와 동선은 순서와 일치한다. 지도 시트가 열려도 노출된 지도는 이동과 확대가 가능하다. [v1.4 §4.1, §5.8, §10]

**수용 기준:** 홈에서 진행중 여행을 선택하면 선택 날짜의 장소와 번호가 지도에 표시된다. 장소 상세와 채팅 시트는 겹치지 않고, 뒤로 가기와 날짜 변경이 일관된다. 범위 밖 전체 장소와 원본 이미지를 무작정 내려받지 않는다.

**후속 또는 조건부:** Mapbox 실제 연결, 3D 지도, TMAP 길찾기, 자동차 확장과 경로 캐시는 무료 범위, 과금 차단, 혼용 허용, 보관 조건을 확인한 뒤 단계적으로 연결한다. 대중교통은 초기 확정 범위가 아니다. [v1.4 §6.1, §6.7, §12]

### MVP 6, 카메라와 여행 기록, CELL

**포함 제안:** CameraX 촬영, 텍스트 기록과 공개 여부, 사진과 위치의 로컬 보관, 서버 동기화와 재시도, 기록 세션의 시작·중지·종료, 화면 꺼짐 중 기록, 서버 H3 CELL 확정, CELL 상세와 최신 대표 사진.

**확정 요구:** 촬영한 사진과 촬영 위치를 함께 보관하고, 업로드가 늦어도 촬영 위치를 기준으로 한다. 활성 여행 기록 세션의 방문도 사진 없이 CELL을 만들 수 있다. 중지와 종료 뒤 새 위치는 제외하고, 중지 전 미전송 샘플은 동기화할 수 있다. H3는 서버에서 계산하며 Android H3 의존성은 추가하지 않는다. [v1.4 §4.2, §4.2.1, §6.4, §6.5]

**수용 기준:** 사진과 위치가 기기에 먼저 남고 동기화 전에는 대기 상태, 동기화 뒤에는 확정 CELL로 구분된다. 같은 CELL의 여러 사진은 권한을 만족하는 최신 사진을 대표로 보이고 상세는 최신순이다. 화면 잠금 전후 활성 세션은 유효 샘플을 이어가며, 중지 뒤 샘플은 새 방문으로 만들지 않는다. 같은 사용자와 CELL의 재전송은 CELL 수와 최초 활성화 EXP를 중복 증가시키지 않는다. [v1.4 §4.2, §6.5, §13]

**측정값의 경계:** 15초, 정확도 30m, 연속 2회와 5초, 전송 5초 또는 30초에서 60초는 실험 시작값이지 보장값이 아니다. 현장 기기에서 재검증한다. [v1.4 §6.6, §12]

### MVP 7, 공개 기록, 발견과 MY

**포함 제안:** 사진별 공개 선택, 공개 기록과 일반 게시물 피드, 좋아요, 댓글, 사용자가 선택한 장소의 바구니 저장, 위치 카드, MY 프로필과 지표와 3열 게시물 그리드.

**확정 요구:** 공개 선택 사진만 발견에 노출한다. 여행 비공개 사진은 여행 구성원에게만 보이고 발견 피드와 공개 지도에는 보이지 않는다. 여러 장소 게시물은 사용자가 선택한 장소만 바구니에 저장한다. MY의 나의 지도는 별도 지도 페이지가 아니라 STOBEE 지도에서 켜고 끈다. [v1.4 §4.5, §4.6, §5.5]

**수용 기준:** 사진별 공개 설정이 피드 노출과 일치한다. 비구성원이 여행 비공개 사진의 API, 썸네일, 원본을 얻지 못한다. 여러 사진을 슬라이드할 수 있고, 댓글에서 프로필로 이동한다. 장소 저장은 선택 여행에 선택 장소만 넣으며 전체 게시물 장소를 일괄 저장하지 않는다. MY의 CELL 수, 여행 수, 좋아요 수는 서버 값과 일치한다.

**후순위 세부:** 레벨 1에서 100과 단계 수식어의 틀은 요구되지만 정확한 EXP 양과 곡선, 삭제와 재등록 정책은 아직 미확정이다. 이를 MVP의 정밀 밸런스로 확정하지 않는다. [v1.4 §4.6, §12]

### MVP 8, STOBEE 주변 탐색

**포함 제안:** 현재 GPS 기반 주변 장소 대화, 최대 5개 추천 카드, 설명 가능한 추천 근거, 동일 장소 지도 마커, 바구니 저장, 현재 위치에서 장소까지 길찾기 표시, 나의 지도 ON/OFF.

**확정 요구:** “근처”는 지도 중심이 아니라 현재 GPS를 기준으로 한다. GPS를 얻지 못하면 위치 확인 상태를 표시하고 임의 기준으로 대체하지 않는다. 추천 카드와 마커는 같은 장소를 가리키며, 장소 선택만으로 AI를 자동 호출하지 않는다. 지도 ON/OFF는 표시만 바꾸고 CELL 수, EXP, 기록 세션을 바꾸지 않는다. [v1.4 §4.4, §5.8, §13]

**수용 기준:** 위치 권한과 GPS가 있으면 최대 5개 카드와 마커가 일치한다. GPS가 없거나 AI 한도에 도달하면 장소 검색과 여행 편집은 유지하고 STOBEE만 제한한다. 외부 AI에 원본 GPS, 개인 사진, 메모, 실명을 보내지 않는다. [v1.4 §9.2]

**조건부 판단:** Gemini 모델 ID, 무료 한도, 계정 과금 상태가 확인되지 않으면 AI를 MVP 연결 항목으로 실행하지 않고 명시적 제한 상태로 둔다. 이는 핵심 장소 검색과 일정 편집을 막지 않는 후퇴 경로다. [v1.4 §9.2, §12]

## 4. MVP 밖으로 미루는 범위

다음은 요구가 없어서 삭제하는 것이 아니라, 작은 MVP의 의존성을 지키기 위한 **PROPOSED 후속 단계**다.

| 후속 단계 | 범위 | 미루는 이유와 근거 |
| --- | --- | --- |
| L1 | 카카오·네이버 지도 공유 링크 | Instagram 이후 우선순위로 명시됐다. 공통 Place와 저장 흐름은 재사용한다. [v1.4 §1.3, §11, §13.2] |
| L2 | 고도화된 동선 최적화, 기간 단축 처리, 음식점 삽입, 운영시간과 점수 세부 정책 | 동선 변경안의 확인과 버전 검사는 요구지만, 기간 단축 처리는 미승인이고 최적화 세부값은 미확정이다. [v1.4 §4.3.4, §12, §12.1] |
| L3 | 자동차 경로, 대중교통, GraphHopper 대안 | TMAP 도보부터 조건부 검증하며 대중교통은 초기 확정 범위가 아니다. [v1.4 §6.7] |
| L4 | STOBEE LLM 고도화와 Instagram LLM 보조 | Instagram 파싱 LLM은 기본 OFF다. 독립 표본에서 정확도, 수정 부담, 비용과 개인정보 조건을 먼저 비교한다. [v1.4 §14.7] |
| L5 | 레벨과 EXP 정밀 밸런싱, 날씨 기반 추천 고도화 | 레벨 틀만 있고 수식과 보상량은 미확정이다. 날씨는 데이터 전략에 남지만 Rain과 Snow 렌더링은 제외됐다. [v1.4 §4.6, §6.1, §12] |
| L6 | 운영 확장 | 추가 서비스, Redis, Kafka, Elasticsearch, 벡터 DB, 마이크로서비스, Kubernetes는 초기 제외다. 단일 Spring MVC와 PostgreSQL로 먼저 검증한다. [v1.4 §9.3, §9.4] |

기간 단축 때 일정 항목을 바구니로 돌릴지, 초대 링크 재발급과 재사용, 의도적인 동일 장소 반복 방문, 원시 위치와 캡션 보관 기간은 별도 결정 전 확정하지 않는다. [v1.4 §12]

## 5. 가장 작은 사용자 여정 순서

1. **가입과 진입:** 사용자가 인증하고 홈을 본다. 인증 실패와 설정 부재는 명시적 오류로 끝난다.
2. **여행 만들기:** 이름, 기간, 지역을 입력하고 여행을 만든다. 생성 후 상태와 권한을 확인한다.
3. **공동 참여:** 초대 링크로 두 번째 사용자가 참여한다. 10분 만료와 역할별 삭제, 나가기 규칙을 확인한다.
4. **장소 찾기:** 자체 검색으로 공통 Place를 찾고 지도 상세에서 확인한다. 검색어와 결과 복귀 상태를 보존한다.
5. **계획 저장:** Place를 바구니에 저장하고 선택 날짜로 이동한다. 이동 실패 시 항목이 사라지지 않는다.
6. **협업 충돌:** 두 사용자가 같은 계획 버전으로 수정한다. 한 명은 저장되고 다른 한 명은 충돌, 최신 조회, 재수정으로 이동한다.
7. **외부 유입:** Instagram 링크를 공유하거나 붙여넣고 후보와 근거를 확인한다. 사용자가 고른 후보만 바구니에 저장한다.
8. **여행 실행:** 홈 여행 카드에서 지도 중심 화면을 열고 날짜, 번호, 동선을 확인한다.
9. **기록:** 카메라 촬영 또는 여행 기록 세션을 시작한다. 화면을 꺼도 세션을 유지하고 중지 뒤 새 위치를 제외한다.
10. **지도와 공유:** 동기화된 CELL과 최신 사진을 확인하고, 공개 선택 사진만 발견과 MY에 연결한다.
11. **발견과 보조:** 발견 또는 STOBEE에서 장소를 선택해 공통 바구니로 되돌아온다. GPS나 무료 AI 조건이 없으면 검색과 계획 기능은 계속 쓴다.

이 순서는 v1.4 §3.1의 주요 흐름, §10의 화면 연결 규칙, §11의 구현 순서를 결합한 제안이다. 기능 요구의 확정 상태와 실제 구현 승인은 구분한다.

## 6. 외부 선행 조건과 중단 기준

외부 연결은 다음 항목을 확인한 뒤에만 실행한다.

1. **인증:** 선택 provider의 공식 SDK, callback, 계정 provisioning, token 수명과 로그아웃, 실제 계정 권한을 확인한다. 현재 저장소의 Kakao local 검증은 production E2E를 대신하지 않는다.
2. **장소 데이터:** 공공 관광과 상권 데이터의 수집, 정규화, 중복 매칭, 이미지와 좌표 품질을 확보한다. 자체 DB가 없으면 검색 성공을 가장하지 않는다. [v1.4 §7]
3. **Instagram:** 허용 대상, URL와 redirect 검증, SSRF 차단, Playwright 격리, 작업 상한과 만료, 원문 보관과 삭제 정책을 확인한다. 로그인, CAPTCHA, 개인 쿠키 우회는 하지 않는다. [v1.4 §14.11]
4. **지도와 길찾기:** Mapbox와 TMAP의 무료 한도, 과금 차단, 지도 위 경로 표시와 캐시 보관 조건을 계정과 약관으로 확인한다. 미확인 시 지도 데이터와 일정 편집을 유료 서비스에 묶지 않는다. [v1.4 §6.1, §6.7, §9.2]
5. **AI:** Gemini의 실제 모델 ID, Free Tier, 한도, 입력 처리 조건과 과금 상태를 확인한다. 실패하면 STOBEE만 제한하고 자체 검색, 장소 상세, 여행 편집은 유지한다. [v1.4 §9.2]
6. **사진과 공개 접속:** 비용 0원 저장 방식, 인증된 파일 API, 썸네일 권한, 용량과 보관, TLS와 외부 접속 경계를 확정한다. 서버 내부 파일 경로를 Android에 노출하지 않는다. [v1.4 §9.1, §9.2]
7. **실기기 검증:** 위치 권한, Foreground Service, 화면 잠금, 배터리, 오프라인 큐, 재전송 중복 방지를 실제 기기에서 확인한다. 15초와 30m 같은 수치는 시험 시작값으로만 기록한다. [v1.4 §6.4, §6.6]

조건을 확인하지 못한 provider나 public endpoint는 연결하지 않고, 해당 기능을 제한 상태로 둔다. secret, 실제 사용자 데이터, local.properties 값은 이 보고서에 넣지 않는다. 기존 real user data와 개발 DB는 보존하며, QA 데이터 정리는 소유한 fixture에만 적용한다.

## 7. 현재 구현과 MVP의 차이

현재 저장소는 Java/XML Android 골격, Kakao 인증, 공통 Place를 TripItem 바구니에 저장하는 backend, 단일 TripItem current GET까지 구현 및 제한된 local 검증이 있다. 여행 CRUD, 전체 바구니 조회와 삭제, 일정 이동과 정렬, real SSE transport, 자체 검색, Instagram 작업, 지도, CameraX, 기록 세션, CELL, 미디어, 발견, MY, STOBEE는 전체 MVP로 검증된 상태가 아니다. [docs/PLAN.md, docs/API.md, docs/BACKEND.md]

따라서 다음 구현 단위는 외부 공개 접근이 아니라 MVP 1의 여행 CRUD와 MVP 2의 Place 검색, 이어서 MVP 3의 전체 바구니와 일정 이동이다. 이는 사용자 최신 지시인 “product MVP FIRST”를 반영하며, v1.4의 단계 2가 인증·Place·TripItem 연결 이후에 오도록 한 순서와도 맞는다. [v1.4 §11, `.omo/artifacts/mvp-first-20261001/notepad.md`]
